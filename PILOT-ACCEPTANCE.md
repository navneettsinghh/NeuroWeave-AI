# CONVERTIQ Pilot Acceptance Checklist

Use this pass/fail checklist for first-client sign-off.

| Area | Pass/Fail | Acceptance Criteria |
| --- | --- | --- |
| Lead capture |  | A new lead can be submitted from the configured pilot source. |
| Normalization |  | Raw lead data is converted into the normalized lead model with required fields. |
| Qualification |  | Configured qualification fields are captured or flagged as missing. |
| Scoring |  | Lead receives HOT/WARM/COLD priority with understandable reasons. |
| Notification |  | A high-priority lead produces an agent-facing recommendation/alert. |
| Follow-up recommendation |  | Follow-up policy returns a recommended action without sending automatically. |
| Human takeover |  | Agent can switch the conversation to Human Active. |
| Status changes |  | Lead can move through pipeline states. |
| Appointment booking |  | Lead can be marked as Booked. |
| Activity timeline |  | Key lead events are visible in lead details. |
| Duplicate detection |  | Same phone/email prompts Existing Lead Found instead of silent duplication. |
| Failure recovery |  | AI/messaging failures show a manual fallback instead of blocking the lead. |
